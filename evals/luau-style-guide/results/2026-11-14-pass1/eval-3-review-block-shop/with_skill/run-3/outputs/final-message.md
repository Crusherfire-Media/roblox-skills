I've written the review to `docs/review.md` and haven't touched the script. It has 11 findings, ordered by how much they matter, each with where it is, what's wrong and what to do instead. These are the ones to fix before building more on it:

1. **A burst of purchases costs only one charge (lines 42–48, 89–97).** Each purchase reads the coin balance from the DataStore, which pauses the handler, then writes it back. If a client sends ten buy requests at once, all ten read the same balance and all ten get blocks, but the coins only drop once. The DataStore calls also aren't wrapped in `pcall`, so a DataStore failure can take the coins without granting the blocks. The fix is to load coins once when the player joins, change them in memory, and save on leave, on an autosave and at shutdown.
2. **Nothing the client sends is checked.** Sending `amt = 0/0` (NaN) gets past every range and price check, because any comparison with NaN is false. That can corrupt the saved balance and give that player unlimited blocks. A position containing NaN gets past the placement rules the same way. Fix: type the arguments as `unknown` and check them first. `BlockTypes.isBlockType` already exists for the block type.
3. **Clearing a block whose owner has left always errors (line 133).** `getOwnerName` returns nothing when the owner isn't found, and `tostring()` with no argument throws. So the feature the comment on line 132 describes doesn't work. Fix: compare UserIds directly.
4. **Once 3 is fixed, clearing an abandoned block gives the remover a free block (line 139).** Separately, purchased stock is only kept in memory, so players lose blocks they paid for when they leave.
5. **Players already in the server when the script starts never get a stock entry.** This is common in Studio Play Solo, and every remote they fire then errors.

The rest are smaller: the receipts setting can never be turned off (line 99), prices are kept separately from `BlockTypes`, clients can flood the server log, `placeBlock` has unclear boolean arguments, the remotes are created at runtime, and some style-guide items.
